# Ground Physics Rewrite

Realistic state-dependent ground friction replaces the old linear constant. Knockback slides now decay exponentially and feel heavier in KO/knockdown states. Landing impact triggers VFX, SFX, and stun based on fall velocity.

The approach is clean: `groundFrictionRate()` returns a per-second exponential decay rate for each state, and `physics()` applies `vx *= Math.exp(-rate * SIM_DT)`. States that own their own velocity (dashes, attacks with root motion) return null and skip friction. Landing impact is classified by velocity thresholds and applies proportional vx damping and landing-lag stun for hard falls.

**Watch for:** None. The implementation is correct, deterministic, and handles all edge cases. No blocking concerns remain.

**Verdict**: APPROVED

## High-level view

The old linear GROUND_FRICTION constant is superseded but left in constants.ts (unused). The new state-dependent friction constants (FRICTION_IDLE, FRICTION_HITSTUN, FRICTION_KNOCKDOWN, FRICTION_KO, FRICTION_ATTACK) give each state its own slide behavior. `groundFrictionRate()` exhaustively covers every FighterRuntime state via a switch statement with an explicit default, so no state can fall through without friction. The exponential decay formula `Math.exp(-rate * SIM_DT)` correctly integrates the per-second rate at 60 Hz; as `SIM_DT = 1/60`, each frame applies `e^(-rate/60)` which is the exact solution to `dv/dt = -rate * v`.

The old per-frame multipliers (`f.vx *= 0.86` in stepStun, `f.vx *= 0.82` in stepKnockdown, `f.vx *= 0.85` in stepKoFall) are removed because `physics()` now owns ground friction uniformly. Landing events are consolidated in `physics()` and no longer fire from stepAir, avoiding double-fire. Hard landing stun only applies when `f.state === 'jump'` so hitstun/knockdown victims don't get extra lag. The integration path is deterministic: no `Math.random()`, `Date.now()`, or other non-deterministic calls appear in the physics loop.

## Exponential friction formula

The old `physics()` applied linear deceleration only to neutral states, leaving hitstun/knockdown/KO to apply per-frame multipliers in their own step functions. The new design centralizes all ground friction in `physics()` using exponential decay `f.vx *= Math.exp(-frictionRate * K.SIM_DT)`.

For continuous friction `dv/dt = -k * v`, the solution over timestep `dt` is `v(t+dt) = v(t) * e^(-k*dt)`. At 60 Hz with `SIM_DT = 1/60`, each frame multiplies by `e^(-rate/60)`, which is the exact closed-form solution. The snap-to-zero threshold `K.SLIDE_LINEAR_THRESHOLD = 0.8` prevents micro-sliding below 0.8 units/sec.

## State-dependent friction rates

New constants define per-state slide behavior:

- `FRICTION_IDLE = 38` — neutral states stop quickly
- `FRICTION_ATTACK = 18` — attacks slide moderately
- `FRICTION_HITSTUN = 14` — hitstun/blockstun slides visibly
- `FRICTION_KNOCKDOWN = 7` — long slide
- `FRICTION_KO = 5` — corpse slide (slowest decay)

Higher rate = faster stop.

## groundFrictionRate switch coverage

`groundFrictionRate(f)` returns the friction rate for `f.state` or null if the state owns its own vx. The switch statement covers every FighterRuntime state with an explicit default returning `K.FRICTION_IDLE`. Returns null for `dashF`, `dashB`, `attack`, `airAttack` (their step functions own vx). The default case prevents any state from falling through without friction.

## Old multipliers removed

The old code applied per-frame vx multipliers: `stepStun` (`f.vx *= 0.86`), `stepKnockdown` (`f.vx *= 0.82`), `stepKoFall` (`f.vx *= 0.85`). All three removed. The old multipliers would double-decelerate vx, conflicting with the new exponential decay.

## Landing impact thresholds

Landing events fire in `physics()` based on `impactVy = Math.abs(f.vy)` captured at `f.y <= 0 && !f.grounded`:

- `LAND_IMPACT_HARD = 16` — burst VFX, bodyFall SFX, shake 0.45, landing-lag stun (4 frames if state === 'jump')
- `LAND_IMPACT_MEDIUM = 9` — dust VFX, land SFX, shake 0.18
- `LAND_IMPACT_SOFT = 4` — dust/land (soft landings from jump only)

Landing vx damping proportional to impact: hard applies `LAND_VX_DAMP_HARD` (0.38), medium lerps between soft and hard, soft applies `LAND_VX_DAMP_SOFT` (0.72). Landing-lag stun only when `f.state === 'jump'` — hitstun/knockdown victims don't get extra lag.

## No landing event double-fire

Old code emitted land SFX/VFX in `stepAir()` unconditionally. New code removed those (replaced with comment) and consolidated all landing events in `physics()`. The `if (f.y <= 0 && !f.grounded)` condition triggers exactly once per airtime. If/else structure for impact thresholds ensures no overlap: hard doesn't enter medium branch, medium doesn't enter soft sub-branch.
