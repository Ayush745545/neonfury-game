# Ground physics rewrite for deterministic friction

This change replaces the single linear GROUND_FRICTION constant with state-dependent exponential decay friction. The rewrite moves friction logic into the centralized `physics()` method, removes scattered per-frame multipliers from state-specific step functions, and adds landing impact thresholds with VFX/SFX feedback and momentum damping.

The approach separates states into two categories: those that manage their own velocity (dash, attack with root motion) return null from `groundFrictionRate()` and skip friction entirely; all other grounded states get exponential decay tuned to their behavioral context (idle stops fast, knockdown slides long). The decay formula `vx *= exp(-rate * dt)` integrates frame-rate-independent deceleration at 60 Hz, with a threshold cutoff to prevent micro-sliding.

**Watch for:** KO cinematic phase (stepKo) still has a leftover `vx *= 0.85` multiplier that duplicates the friction applied by `physics()` (**confirmed**). Landing events fire correctly for hard/medium impacts without double-firing with existing stepAir logic, but the control flow uses nested if/else to prevent overlap.

**Verdict**: NEEDS_CHANGES

## High-level view

The new friction system routes all ground deceleration through `groundFrictionRate()`, which maps each FighterRuntime state to a friction constant or null for states with custom velocity control. The exponential decay formula is mathematically correct for frame-rate-independent integration and will produce stable results at 60 Hz.

State coverage is comprehensive: every defined state is either explicitly handled or caught by the default case, though `jump` and `airHitstun` only reach the friction logic in edge-case transitions since they're normally airborne.

The old GROUND_FRICTION constant remains defined in constants.ts but is no longer referenced in the physics path — it was only used in the previous physics() implementation, now replaced.

Landing impact detection introduces three thresholds (soft, medium, hard) with proportional VFX/SFX and velocity damping. Hard landings also apply brief stun frames to the `jump` state. The logic avoids double-firing by using if/else chains and only emits medium-tier events if the impact wasn't already hard.

The KO cinematic phase has a regression: `stepKo()` calls `physics(f, false)` and then applies `f.vx *= 0.85`, which doubles up on friction since `physics()` already applied FRICTION_KO exponential decay.

## Issues (1)

1. **KO cinematic friction duplication** — stepKo() applies `f.vx *= 0.85` after calling `physics()`, which already applied FRICTION_KO exponential decay. Remove the manual multiplier and let the centralized friction system handle it.

## Exponential decay integration

The friction formula is:

```typescript
const decay = Math.exp(-frictionRate * K.SIM_DT);
f.vx *= decay;
```

This is the correct discrete approximation for exponential decay `v(t) = v₀ * exp(-k*t)` at a fixed time step. At 60 Hz (SIM_DT = 1/60), the formula integrates smoothly and avoids overshoot or instability. The cutoff threshold (SLIDE_LINEAR_THRESHOLD = 0.8) snaps small velocities to zero, preventing floating-point micro-sliding.

## State-dependent friction routing

`groundFrictionRate()` maps states to friction constants:

```typescript
private groundFrictionRate(f: FighterRuntime): number | null {
  switch (f.state) {
    case 'dashF': case 'dashB': return null;
    case 'attack': case 'airAttack': return null;
    case 'hitstun': case 'blockstun': return K.FRICTION_HITSTUN;
    case 'knockdown': return K.FRICTION_KNOCKDOWN;
    case 'ko': return K.FRICTION_KO;
    case 'idle': case 'walkF': case 'walkB':
    case 'crouch': case 'crouchWalkF': case 'crouchWalkB':
    case 'blockStand': case 'blockCrouch':
    case 'getup': case 'victory': case 'defeat':
    case 'introWalk': case 'introIdle': case 'superVictim':
      return K.FRICTION_IDLE;
    default:
      return K.FRICTION_IDLE;
  }
}
```

Every state in the FighterState type union is either explicitly listed or caught by the default case. `jump` and `airHitstun` are airborne states, so they won't reach the friction logic unless a timing edge causes them to be grounded, in which case the default returns FRICTION_IDLE (safe fallback).

States that return null (`dashF`, `dashB`, `attack`, `airAttack`) have velocity managed by their step functions (stepDash applies ease-out curves, runMoveFrames applies root motion from move definitions). The null check skips friction for these states, preventing interference.

## Removed per-frame multipliers

The prior implementation had scattered `vx *= 0.something` lines in stepStun, stepKnockdown, and stepKoFall. These are gone — confirmed by reading those methods:

```typescript
private stepStun(f: FighterRuntime, opp: FighterRuntime): void {
  if (this.tryBurstEscape(f)) return;
  if (f.stateFrame >= f.stunFrames) {
    // ... transition to idle/block
  }
  // no vx manipulation
}

private stepKnockdown(f: FighterRuntime): void {
  if (f.grounded && this.tryBurstEscape(f)) return;
  if (f.grounded && f.stateFrame > K.KNOCKDOWN_LIE_FRAMES + ...) {
    this.enter(f, 'getup');
  }
  // no vx manipulation
}

private stepKoFall(f: FighterRuntime): void {
  // physics() now handles ground friction via FRICTION_KO
  void f;
}
```

The comment in stepKoFall explicitly confirms the intent.

## KO cinematic friction duplication

The `stepKo()` method (distinct from `stepKoFall()` — stepKo is the phase handler for the entire KO cinematic, stepKoFall is the per-fighter state step) has this code:

```typescript
private stepKo(): void {
  const m = this.match;
  const t = m.phaseFrame;
  for (const f of m.fighters) {
    if (f.hitstop > 0) { f.hitstop--; continue; }
    f.stateFrame++;
    if (f.state === 'ko') {
      this.physics(f, false);
      if (f.grounded) f.vx *= 0.85;  // ← problem: duplicates friction
    } else if (f.state !== 'victory') {
      // winner logic
      f.vx = 0;
      if (f.state === 'attack' || f.state === 'hitstun') this.enter(f, 'idle');
      this.physics(f, false);
    }
  }
  // ... rest of KO phase logic
}
```

Line 1616 applies `f.vx *= 0.85` immediately after calling `physics(f, false)`. Since the fighter is in the 'ko' state and grounded, `physics()` already applied exponential decay via `groundFrictionRate()` returning FRICTION_KO (5 units/s²). The manual multiplier adds a second, conflicting deceleration on top of the exponential curve.

The fix: remove the `if (f.grounded) f.vx *= 0.85;` line. The centralized friction system in `physics()` already handles the ko state correctly.

## Landing impact thresholds

The landing logic in `physics()` captures the absolute vertical velocity at the moment of ground contact, then applies damping, VFX, and stun based on thresholds:

```typescript
if (f.y <= 0 && !f.grounded) {
  f.y = 0;
  const impactVy = Math.abs(f.vy);

  // vx damping proportional to impact
  if (impactVy >= K.LAND_IMPACT_HARD) {
    f.vx *= K.LAND_VX_DAMP_HARD;  // 0.38
  } else if (impactVy >= K.LAND_IMPACT_MEDIUM) {
    const t = (impactVy - K.LAND_IMPACT_MEDIUM) / (K.LAND_IMPACT_HARD - K.LAND_IMPACT_MEDIUM);
    f.vx *= K.LAND_VX_DAMP_SOFT + (K.LAND_VX_DAMP_HARD - K.LAND_VX_DAMP_SOFT) * t;
  } else if (impactVy >= K.LAND_IMPACT_SOFT) {
    f.vx *= K.LAND_VX_DAMP_SOFT;  // 0.72
  }

  f.vy = 0;
  f.grounded = true;

  // VFX/SFX
  if (impactVy >= K.LAND_IMPACT_HARD) {
    bus.emit({ type: 'sfx', name: 'bodyFall', gain: 1.1 });
    bus.emit({ type: 'vfx', kind: 'burst', ... });
    bus.emit({ type: 'shake', intensity: 0.45 });
    if (f.state === 'jump') {
      f.state = 'hitstun';
      f.stateFrame = 0;
      f.stunFrames = K.LAND_HARD_STUN_FRAMES;
    }
  } else if (impactVy >= K.LAND_IMPACT_MEDIUM) {
    bus.emit({ type: 'sfx', name: 'land' });
    bus.emit({ type: 'vfx', kind: 'dust', ... });
    bus.emit({ type: 'shake', intensity: 0.18 });
  }

  // state transitions
  if (f.state === 'jump' && impactVy < K.LAND_IMPACT_HARD) {
    this.enter(f, 'idle');
    if (impactVy < K.LAND_IMPACT_MEDIUM) {
      bus.emit({ type: 'sfx', name: 'land' });
      bus.emit({ type: 'vfx', kind: 'dust', ... });
    }
  }
}
```

The if/else chain for VFX emission prevents hard landings from also emitting medium-tier effects. The state transition block only runs for `jump` state and uses another if/else to emit soft-land events only if the impact wasn't already medium or hard.

This doesn't cover all landing cases — `airHitstun` and `knockdown` transitions on landing are handled in `stepAirHitstun()` and don't pass through this VFX logic. That's intentional: hitstun/knockdown landings have their own VFX (dust on knockdown landing, different intensity). The hard-landing stun (`f.state = 'hitstun'`) only applies if the fighter was in `jump` state, not if they were already in hitstun or other committed states.

## Old GROUND_FRICTION constant

The constant is still defined in constants.ts:

```typescript
export const GROUND_FRICTION = 10.5;     // knockback slide decel
```

But it's no longer referenced anywhere in the codebase. The previous `physics()` implementation used it directly; the new implementation uses the state-dependent constants (FRICTION_IDLE, FRICTION_HITSTUN, FRICTION_KNOCKDOWN, FRICTION_KO) instead.

The old constant could be removed, but leaving it doesn't cause problems — it's dead code. If this were a public API or library, removing it would be a breaking change, but in a game engine it's just cleanup.

## Determinism check

No Math.random() or Date.now() calls exist in the physics path. Date.now() appears once in the constructor to generate a seed, which is stored and used with the deterministic mulberry32 PRNG. The physics() method and all state step functions use only deterministic operations: arithmetic, Math.exp, Math.abs, comparisons. SIM_DT is a constant (1/60).

The exponential decay formula uses Math.exp, which is deterministic (IEEE 754 guarantees bit-identical results for the same input on the same platform). At 60 Hz with the chosen friction rates, the decay values are well within the stable range (no denormals, no catastrophic cancellation).
